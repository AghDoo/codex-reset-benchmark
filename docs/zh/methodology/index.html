評分方法 1.1

預測目標

本 benchmark 評分正式 checkpoint 後 5h、24h 或 48h 內，是否出現新的、符合定義的廣泛／全域 Codex 用量重置公開事件。個人 rolling reset、banked credit、reset button 線索、模糊承諾與個別帳戶事件皆排除。

正式 Checkpoint

UTC 00:00、06:00、12:00、18:00。5h 只取 1 小時內最新 archive forecast；24h/48h 可取 6 小時內最新 forecast，因此高頻更新網站不會得到額外權重。

Common-case 排名

Methodology 1.1 的正式排名，只使用同一 horizon 的 ranking cohort 中，所有來源都具有 fresh forecast 的已結算 checkpoint 交集。缺失預測不做插值，避免來源因剛好漏掉困難 checkpoint 而取得不公平優勢。

Score 樣本是正式指標共同使用的 cases；Coverage則是來源實際提供的所有 fresh 已結算 cases，Availability 仍維持來源自身覆蓋率。

主指標

Brier = (p - o)²，越低越好。Calibration、Log Loss、二元 Hit Rate、Availability、Score 樣本與 Coverage 為輔助診斷。共同 score cases 至少累積 10 筆後才給正式排名。

Ground Truth

只有 data/events/resets.json 中經審核且 status=confirmed 的事件才參與評分。完整 forecast window 必須落在 dataset 的 reviewed_at 之前才可結算。Banked reset 與只有 signal 的公告會保留為 excluded audit evidence，但永遠不算 positive outcome。

可稽核性

Forecast NDJSON 採 append-only。本專案不重新發布第三方完整頁面，只保存正規化機率、時間戳、來源 URL、collector metadata 與取得內容的 SHA-256。
